# ТЗ: универсальный конвертер документов (PDF и изображения → Excel / Word)

Документ адресован ИИ-разработчику (и человеку-руководителю проекта). По нему нужно построить программу, которая принимает PDF и графические файлы и выдаёт Excel (.xlsx) и/или Word (.docx), **максимально точно** воспроизводящие содержимое исходника.

Требования пронумерованы (FR — функциональные, NFR — нефункциональные), чтобы на них можно было ссылаться в тестах и отчётах. Слова: **должна** — обязательно (Must), **следует** — желательно (Should), **может** — по возможности (Could).

---

## 0. Инструкция исполнителю (ИИ)

1. Прочитай ТЗ целиком. Выпиши неясности. Если по ним есть решение по умолчанию (раздел 12) — прими его и запиши в `DECISIONS.md`. Если решение дорогое или необратимое (платный сервис, отправка данных наружу) — спроси заказчика.
2. Работай этапами (раздел 10). Сначала MVP, потом остальное.
3. **Сначала тесты и эталоны (раздел 9), потом код.** Не расширяй функции, пока MVP не проходит свои тесты.
4. Не выдавай непроверенное за проверенное. «Работает» означает «запустил и увидел результат». В отчёте отдельно укажи: что запускалось, что нет, что проверено только чтением документации.
5. Не придумывай API. Версии библиотек, названия функций и параметры проверяй по документации или интроспекцией в установленной версии.
6. **Главный принцип (раздел 1.2) важнее скорости, красоты и числа функций.** Лучше пометить значение как сомнительное, чем выдать красивое, но неверное.
7. Если встретился файл, с которым программа не справляется, — это нормальный результат, но программа обязана сказать об этом явно, а не молча выдать плохой файл.

## 1. Кратко

### 1.1. Что делает программа

| | |
|---|---|
| **Вход** | PDF (с текстовым слоем, сканы, смешанные), изображения (JPEG, PNG, TIFF и др.), фото документов с телефона |
| **Выход** | `.xlsx` и/или `.docx`; дополнительно JSON с промежуточным представлением, HTML-отчёт для проверки |
| **Содержимое** | таблицы → настоящие таблицы Excel с настоящими числами; текст → Word со структурой (заголовки, абзацы, списки, таблицы, картинки) |
| **Режимы** | универсальный (любой документ) и по профилю (документ известного типа: счёт, акт и т. п.) с проверками |

### 1.2. Главный принцип точности

Три гарантии, на которых строится вся программа:

- **G1. Верность.** Значения переносятся такими, как напечатаны. Ничего не «исправляется» молча: ни опечатки источника, ни неверные итоги, ни странные формулировки.
- **G2. Прозрачность.** Каждое значение привязано к месту на исходной странице и к уровню уверенности. Сомнительное и нечитаемое видно в результате.
- **G3. Проверяемость.** После обработки есть отчёт: что проверено, что сошлось, что нет, что не прочитано.

**Жёсткое правило:** программа никогда не подставляет «правдоподобное» значение, которого нет в источнике. Нечитаемое остаётся нечитаемым и помечается.

### 1.3. Допущения

- «Перевод в Excel/Word» понимается как **конвертация формата**, а не перевод с языка на язык. Языковой перевод — вне ядра (раздел 3).
- Основные языки документов: русский и английский; остальные задаёт заказчик (раздел 12).
- Рукописный текст не входит в MVP.

## 2. Термины

- **IR** (промежуточное представление) — внутренняя модель документа в JSON (приложение A). Из неё строятся все выходные файлы.
- **Движок** — подключаемый компонент распознавания (OCR, мультимодальная модель, разбор таблиц).
- **Профиль** — декларативное описание документа известного типа: колонки, типы, правила проверки (приложение B).
- **Флаг** — пометка значения: `low_confidence`, `unreadable`, `mixed_script`, `check_failed` и др.
- **Тихая ошибка** — неверное значение в результате **без** флага. Главный враг этого проекта.

---

## 3. Область

**В области:** чтение PDF и растровых изображений; распознавание текста и таблиц; нормализация чисел и дат; проверки согласованности; экспорт в `.xlsx` и `.docx`; отчёт; CLI; библиотека; простой интерфейс (следует).

**Вне области:** перевод с языка на язык (может быть плагином позже); редактирование исходных PDF; электронная подпись; распознавание рукописного текста (в MVP); взлом защищённых файлов; видео.

## 5. Архитектура

### 5.1. Конвейер

```text
Ввод → Подготовка страниц → Разметка → Распознавание → Сборка структуры
     → Нормализация → Проверка → Экспорт (xlsx / docx / json / html) → Отчёт
```

Каждый этап — отдельный модуль с описанным интерфейсом, свои тесты. Движки распознавания и экспортёры подключаются как плагины.

### 5.2. Правила архитектуры

- **FR-ARC-1.** Все выходные файлы строятся **только из IR**, а не напрямую из распознавания.
- **FR-ARC-2.** Каждый элемент IR хранит страницу, координаты (bbox) на **исходном** изображении, уверенность, движок, флаги и (при сомнении) альтернативные значения.
- **FR-ARC-3.** Любое преобразование геометрии (поворот, выравнивание, масштаб) записывается, чтобы координаты можно было вернуть на исходник.
- **FR-ARC-4.** Движки взаимозаменяемы через единый интерфейс; выбор — настройкой, без правки кода.
- **FR-ARC-5.** Профили и пользовательские правила — данные (YAML/JSON), а не код.

### 5.3. Варианты движков (примеры, актуальность проверить на момент разработки)

| Класс | Примеры | Заметки |
|---|---|---|
| Локальный OCR | Tesseract, PaddleOCR, EasyOCR | работает офлайн; качество по таблицам и печатям нужно измерять |
| Облачный разбор документов | Google Document AI, Azure AI Document Intelligence, Amazon Textract | данные уходят наружу — см. NFR-PRIV |
| Мультимодальные модели | модели с компьютерным зрением (в т. ч. Claude) | хорошо читают таблицы и сложную вёрстку; нужны строгий формат ответа, проверки и второй проход |

Исполнитель выбирает движки по результатам измерений на контрольном наборе (раздел 9), а не по репутации.

## 6. Функциональные требования

### 6.1. Ввод (FR-IN)

- **FR-IN-1.** Принимать PDF, JPEG, PNG, TIFF (в т. ч. многостраничный), BMP, WebP. HEIC и GIF — следует.
- **FR-IN-2.** Определять тип по содержимому, а не по расширению.
- **FR-IN-3.** Принимать файл, несколько файлов, папку (рекурсивно), ZIP. Порядок страниц сохраняется. По умолчанию один входной файл даёт один выходной; сливать — опция.
- **FR-IN-4.** Для каждой страницы PDF определять, есть ли **настоящий** текстовый слой: считать непробельные символы (вывод из одних переводов страниц и пробелов — это скан). Смешанные PDF обрабатывать постранично.
- **FR-IN-5.** Текстовому слою доверять, но проверять на мусор (нечитаемая кодировка, символы-заменители, нет соответствия юникоду). При подозрении переходить на распознавание изображения и сообщать об этом.
- **FR-IN-6.** Учитывать поворот страницы PDF (`/Rotate`) и ориентацию EXIF у фото.
- **FR-IN-7.** Файл, защищённый паролем: запросить пароль или отказать с понятным сообщением. Не подбирать.
- **FR-IN-8.** Повреждённые, пустые файлы и изображения, не являющиеся документами: понятная ошибка **по файлу**; пакет продолжается.
- **FR-IN-9.** Настраиваемые лимиты (размер, число страниц, размер в пикселях) и защита от «бомб» (огромные изображения, вложенные архивы).

### 6.2. Подготовка страниц (FR-PRE)

- **FR-PRE-1.** Приводить страницу к рабочему разрешению не ниже 300 dpi (настраиваемо). Не уменьшать ниже исходного. Записывать **исходное** разрешение: увеличение выше исходного деталей не добавляет.
- **FR-PRE-2.** Автоповорот (0/90/180/270) и устранение наклона; ориентацию определять по содержимому.
- **FR-PRE-3.** Для фото: коррекция перспективы, обрезка по краю листа, выравнивание освещения и теней — опционально. Не терять содержимое у краёв.
- **FR-PRE-4.** Улучшение (шумоподавление, контраст, бинаризация) — отдельные опции. Оригинал сохранять.
- **FR-PRE-5.** Оценивать качество страницы (разрешение, резкость, контраст) и предупреждать, если качество низкое и точность под вопросом.
- **FR-PRE-6.** Разделение разворотов (две страницы на листе) — следует.

### 6.3. Разметка страницы (FR-LAY)

- **FR-LAY-1.** Находить блоки: заголовки, абзацы, списки, таблицы, рисунки, колонтитулы, номера страниц, печати/штампы, подписи.
- **FR-LAY-2.** Определять порядок чтения: многоколоночная вёрстка, сноски, врезки.
- **FR-LAY-3.** **Печати, штампы и подписи:** не терять текст под ними. Область помечать, текст под печатью читать отдельным проходом с пометкой пониженной уверенности. Текст самой печати не вставлять в основной текст без пометки.
- **FR-LAY-4.** Рисунки и логотипы сохранять как изображения (Word — вставлять; Excel — опционально).

### 6.4. Распознавание текста (FR-OCR)

- **FR-OCR-1.** Движок сменный (FR-ARC-4). В MVP — минимум один локальный; облачный или мультимодальный — следует.
- **FR-OCR-2.** Языки задаются списком; автоопределение; несколько языков на странице допустимы.
- **FR-OCR-3.** Для каждого слова, строки и ячейки: текст, bbox, уверенность; при сомнении — альтернативы.
- **FR-OCR-4.** **Нечитаемое не угадывать.** Значение получает флаг `unreadable` и в выходном файле представлено явной меткой, а не «наиболее вероятным» вариантом. Сомнительное значение сохраняется, но подсвечивается.
- **FR-OCR-5.** Переносить текст **как напечатано**: сохранять опечатки источника, регистр, знаки препинания. Пробелы — по правилу FR-NORM-5.
- **FR-OCR-6.** Буквы-двойники кириллицы и латиницы (раздел 8, п. 5) обрабатывать по правилам FR-VER-5.
- **FR-OCR-7.** Рукописный текст: помечать как «рукописный, не распознан». Попытка распознавания — может, с обязательной пометкой.

### 6.5. Таблицы (FR-TBL)

- **FR-TBL-1.** Распознавать таблицы с линиями и без линий (по выравниванию колонок).
- **FR-TBL-2.** Объединённые ячейки (rowspan/colspan): в IR значение хранится один раз; при экспорте — как объединённая ячейка. Опция `unmerge_fill` копирует значение на каждую строку объединения (нужна для «плоских» таблиц и фильтров).
- **FR-TBL-3.** Многострочные ячейки (перенос внутри ячейки).
- **FR-TBL-4.** Многоуровневые заголовки; повёрнутые таблицы.
- **FR-TBL-5.** Таблица, продолжающаяся на следующих страницах: склеивать по признаку (повторяющаяся шапка, то же число колонок) **и** помечать склейку. При неуверенности не склеивать, а сообщить.
- **FR-TBL-6.** **Повторяющиеся одинаковые строки не удалять и не объединять.** Порядок строк сохранять.
- **FR-TBL-7.** Строки итогов и подытогов распознавать как итоговые (флаг), но не пересчитывать молча.
- **FR-TBL-8.** Проверять структуру: одинаковое число колонок во всех строках с учётом объединений. Нарушение — флаг.

### 6.6. Нормализация (FR-NORM)

- **FR-NORM-1.** Хранить два значения: `raw` (как напечатано) и `value` (разобранное, с типом). Любое изменение относительно `raw` фиксируется.
- **FR-NORM-2.** Числа: запятая или точка как десятичный разделитель; пробел, неразрывный пробел, апостроф как разделитель тысяч; знак валюты слева или справа; отрицательные со знаком или в скобках; проценты. Неоднозначные случаи (`1,234`) **не угадывать молча** — флаг и выбор по профилю.
- **FR-NORM-3.** **Идентификаторы** (артикулы, коды, номера документов, ИНН, телефоны, штрихкоды) — всегда текст. Ведущие нули сохранять. Не превращать в числа и даты.
- **FR-NORM-4.** Даты: разбирать по известному формату; неоднозначные (`03/04/2026`) — флаг.
- **FR-NORM-5.** Пробелы: любую последовательность пробельных символов, включая перенос строки внутри ячейки, заменять одним пробелом и обрезать края (можно отключить). Других правок текста не делать.
- **FR-NORM-6.** Правила нормализации задаются профилем или конфигом.

### 6.7. Проверка точности (FR-VER) — ключевой раздел

- **FR-VER-1.** Уверенность на каждое значение; порог «подозрительно» настраивается.
- **FR-VER-2.** **Второй независимый проход.** Для сомнительных значений (и, по настройке, для всех): другой движок, другая нарезка или другой масштаб. Расхождение разрешается увеличенным фрагментом **одной ячейки**; если не разрешилось — флаг для человека.
- **FR-VER-3.** Правила согласованности (из профиля): сумма столбца = итог; количество × цена = сумма; формат (шаблон, диапазон, контрольные цифры); согласованность между документами комплекта. Результат каждого правила: `ok` / `failed` / `skipped` с объяснением.
- **FR-VER-4.** **Итог в самом документе может быть неверным.** Если правило не сошлось, но все слагаемые прочитаны уверенно, — это находка источника. Значения не «подгоняются»; в отчёте оба числа и разница, в Excel — пометка.
- **FR-VER-5.** Предупреждения: слова со смешением алфавитов; подозрительные пары символов (О/0, l/1/I, Ш/Щ, З/3); слова вне словаря языка — как «опечатка источника или ошибка распознавания». Текст не исправляется.
- **FR-VER-6.** Итог по документу: доля значений высокой уверенности, число флагов, число нечитаемого, результаты правил; статус «готово» / «требует проверки» / «не удалось».
- **FR-VER-7.** Арифметические проверки **недостаточны**: ошибка в наименовании или коде суммы не меняет. Поэтому FR-VER-2 обязателен.

### 6.8. Экспорт в Excel (FR-XLS)

- **FR-XLS-1.** Формат `.xlsx`. Одна таблица — один лист (или блок на листе — настройка). Имя листа ≤ 31 символа, без `[ ] : * ? / \`, уникальное.
- **FR-XLS-2.** Типы: числа — числовые ячейки с форматом, повторяющим число знаков из источника; даты — даты; **идентификаторы — текст**.
- **FR-XLS-3.** Объединённые ячейки сохранять (FR-TBL-2).
- **FR-XLS-4.** Текст, начинающийся с `=`, `+`, `-`, `@`, записывать **строкой** (не формулой): защита от случайных и злонамеренных формул.
- **FR-XLS-5.** Числа с 16 и более значащими цифрами (штрихкоды, номера) записывать текстом: Excel хранит только 15 значащих цифр.
- **FR-XLS-6.** Ограничения Excel (≤ 1 048 576 строк, ≤ 16 384 столбцов, ≤ 32 767 символов в ячейке): при превышении разбивать и сообщать.
- **FR-XLS-7.** Сомнительное и нечитаемое — заливка и примечание (альтернативы, страница, область); легенда на листе.
- **FR-XLS-8.** Служебные листы: «Отчёт» (результаты проверок, находки) и «Источник» (для каждой ячейки: страница, область, уверенность).
- **FR-XLS-9.** Формулы по умолчанию не добавлять. По желанию — формулы проверки итогов; значения из документа пишутся значениями, расчётные — формулами и помечаются.
- **FR-XLS-10.** Файл открывается без предупреждений в Excel и LibreOffice; значения формул (если есть) вычислены.

### 6.9. Экспорт в Word (FR-DOC)

- **FR-DOC-1.** Формат `.docx`. Заголовки — стилями заголовков; списки — настоящими списками; таблицы — настоящими таблицами; изображения; разрывы страниц; колонтитулы.
- **FR-DOC-2.** Два режима: «структурный» (чистая семантика; по умолчанию) и «по вёрстке» (максимально похоже на оригинал: поля, колонки, положение). «По вёрстке» — следует.
- **FR-DOC-3.** Порядок чтения сохранять; многоколоночный текст не ломать.
- **FR-DOC-4.** Шрифт подбирать близкий; жирный, курсив, подчёркивание сохранять, где распознано.
- **FR-DOC-5.** Сомнительные фрагменты — выделение и комментарий (выключается).
- **FR-DOC-6.** Печати, подписи, логотипы — изображениями с подписью-меткой.
- **FR-DOC-7.** Таблицы — по тем же правилам, что в Excel (объединения, многострочные ячейки).
- **FR-DOC-8.** Файл открывается без ошибок в Word и LibreOffice.

### 6.10. Проверка человеком (FR-REV)

- **FR-REV-1.** HTML-отчёт: каждая пометка — вырезка исходного изображения рядом с распознанным значением и альтернативами. Следует.
- **FR-REV-2.** Импорт исправленного человеком файла обратно в IR и пересборка выходов. Может.

### 6.11. Интерфейсы (FR-IF)

- **FR-IF-1.** CLI для пакетной обработки. Пример: `convert input/ --to xlsx,docx --lang ru,en --profile invoice --engine local --out result/`.
- **FR-IF-2.** Библиотека с теми же возможностями.
- **FR-IF-3.** Локальный интерфейс (перетащить файлы, выбрать формат и язык, прогресс, результат и отчёт). Следует.
- **FR-IF-4.** Конфиг в YAML/JSON; режимы `--dry-run` и `--explain` (что будет сделано и почему).
- **FR-IF-5.** Машинный отчёт в JSON и коды возврата для автоматизации.
- **FR-IF-6.** Профили (приложение B). Без профиля — универсальный режим.
- **FR-IF-7.** Плагины: движки, профили, экспортёры.

## 7. Нефункциональные требования

- **NFR-ACC (точность).** Метрики и ориентиры — раздел 9. Главный показатель — доля **тихих ошибок**; цель — ноль на контрольном наборе. Рост числа флагов предпочтительнее роста тихих ошибок.
- **NFR-PERF (скорость).** Ориентир: типовая страница A4 обрабатывается за секунды на обычном ПК без видеокарты (число согласовать). Постраничная потоковая обработка: большой PDF не загружается в память целиком. Параллелизм настраивается.
- **NFR-PRIV (конфиденциальность).** По умолчанию всё локально. Облачные и внешние сервисы — только по явному включению, с предупреждением и списком того, что уходит наружу. Содержимое документов не попадает в логи и телеметрию; временные файлы удаляются; ключи — из переменных окружения или хранилища секретов, не в коде и не в конфигах.
- **NFR-PLAT (платформы).** Windows, Linux, macOS (подтвердить у заказчика). Установка одной командой или контейнер.
- **NFR-LIC (лицензии).** Составить таблицу лицензий зависимостей и проверить совместимость с целевым использованием. Некоторые популярные PDF-библиотеки распространяются под AGPL: такие случаи согласовывать с заказчиком.
- **NFR-REP (воспроизводимость).** Отчёт содержит версии программы и движков, конфиг, SHA-256 входа. Один вход и один конфиг дают один результат (в пределах детерминизма движков).
- **NFR-LOG.** Уровень INFO — без содержимого документов. Уровень DEBUG с содержимым — отдельно и с предупреждением.
- **NFR-ERR.** Ошибка одного файла не останавливает пакет; в отчёте причина по каждому файлу.
- **NFR-I18N.** Интерфейс и сообщения: русский и английский.
- **NFR-MAINT.** Тесты, типизация, CI, документация для разработчика.

## 8. Известные ловушки (уроки пилота на реальных счетах и упаковочных листах)

Это не пожелания, а то, что реально ломалось. Каждая ловушка должна иметь тест.

1. **Скан выглядит как «текст есть».** `pdftotext` для скана возвращает только символы перевода страницы (по одному на страницу; для 14-страничного пилотного файла — 14 байт). Проверка «вывод не пуст» ошибётся; считать непробельные символы (FR-IN-4).
2. **Страница повёрнута метаданными.** Картинка может лежать «боком»; поворот PDF (`/Rotate`) учитывается при рендере, но не при простом извлечении картинок (FR-IN-6).
3. **Разрешение.** Скан был 200 ppi; рендер в 300 dpi деталей не добавил. На уменьшенных превью появлялись ложные «опечатки» (`Patentes` читалось как `Pateates`).
4. **Печать поверх текста** ломает распознавание наименований, количеств и итогов (FR-LAY-3).
5. **Буквы-двойники.** Ш/Щ, О/0, З/3; кириллические и латинские А, В, С, Е, Н, К, М, О, Р, Т, Х, У выглядят одинаково. В пилоте «КЛЕ**Ш**Е» первый раз прочитали как «КЛЕ**Щ**Е»; ошибку нашла только независимая перечитка. Для сравнения приводить визуально неразличимые буквы к одному алфавиту; смешанные слова — в предупреждения (FR-VER-5).
6. **Объединённая ячейка на несколько строк.** Вес брутто был один на всё место, при нескольких позициях в нём. Не терять и не дублировать молча; опция `unmerge_fill` (FR-TBL-2). Номер места в такой объединённой ячейке тоже один на все строки.
7. **Одинаковые строки — это данные.** Три идентичные строки (артикул, наименование, размеры, вес) на разных паллетах — три позиции. Дедупликация и склейка по содержимому запрещены (FR-TBL-6).
8. **Итог в документе был неверным.** В счёте итог не включал последнюю строку (разница равна ровно её стоимости). Правила проверки это ловят; значения не подгонять (FR-VER-4).
9. **Опечатки источника** (`ЭЛЕКТРОНУМАТИЧЕСКИЙ`) сохраняются и выносятся в замечания; не исправляются (FR-OCR-5).
10. **Числа:** `4 500,00`, `4500,000`, `€ 1 680,00`, `1 680,00 €`. Разные форматы в одном документе (FR-NORM-2).
11. **Двойные пробелы и переносы внутри ячейки** (`ПЛАТА ТЕМПЕРАТУРЫ  (PT100)`) не должны давать ложных расхождений (FR-NORM-5).
12. **Одинаковые названия — разные сущности.** «№ паллеты» в счёте и «место» в упаковочном листе — разная нумерация; сопоставлять по порядку строк и по правилам профиля, а не по названию колонки.
13. **Арифметика не ловит всё.** Ошибка в наименовании или коде на суммы не влияет. Нужен второй проход (FR-VER-2, FR-VER-7).
14. **Excel сам портит данные:** строка с `=` становится формулой (FR-XLS-4); ведущие нули теряются (FR-NORM-3); числа длиннее 15 цифр теряют точность (FR-XLS-5). CSV для результата не использовать: при открытии в Excel данные «улучшаются» автоматически.
15. **Первый проход распознавания ошибается.** Принимать результат без второго прохода и без флагов нельзя, даже при высокой средней точности.

## 9. Тестирование и приёмка

### 9.1. Контрольный набор

Хранится в репозитории: входные файлы, эталон в JSON (проверен человеком дважды), описание. Не использовать реальные персональные данные без разрешения или анонимизации.

Обязательные категории:

| Категория | Что проверяет |
|---|---|
| Чистый PDF с текстовым слоем | быстрый путь; текст 100 % |
| Скан 200–300 dpi, печатный | базовое качество |
| Скан со штампом поверх текста | FR-LAY-3 |
| Фото с телефона: наклон, перспектива, тени | FR-PRE-2/3 |
| Таблица с линиями и без линий | FR-TBL-1 |
| Объединённые ячейки; повторяющиеся строки | FR-TBL-2/6 |
| Таблица на нескольких страницах | FR-TBL-5 |
| Два языка на странице; кириллица и латиница | FR-OCR-2, FR-VER-5 |
| Многоколоночный текст, списки, заголовки | FR-LAY-2, FR-DOC |
| Страница с поворотом 90° в метаданных | FR-IN-6 |
| Документ с неверным итогом | FR-VER-4 |
| Низкое качество, размытый, тёмный | FR-PRE-5, флаги |
| Негативные: пустая страница, повреждённый файл, файл с паролем, не документ | FR-IN-7/8 |

### 9.2. Метрики

- Текст: CER и WER (доля ошибочных символов и слов).
- Таблицы: точность на уровне ячеек; метрика структуры (например, TEDS).
- Числа и идентификаторы: точное совпадение.
- **Тихие ошибки:** число неверных значений без флага (главный показатель).
- Полнота флагов: какая доля реальных ошибок была помечена.

### 9.3. Критерии приёмки MVP (ориентиры — согласовать с заказчиком)

1. На контрольном наборе **ноль тихих ошибок в числовых полях и идентификаторах**.
2. Чистый PDF с текстовым слоем: текст совпадает полностью.
3. Чистые печатные сканы: числа и идентификаторы совпадают с эталоном не менее чем в 99,5 % значений (число — ориентир). Остальные значения помечены флагом.
4. Все файлы категории «негативные» дают понятную ошибку и не останавливают пакет.
5. Excel и Word открываются без предупреждений в Excel/Word и LibreOffice.
6. Все ловушки раздела 8 покрыты тестами.
7. Отчёт содержит все проверки, находки и нечитаемое; статус документа соответствует содержимому.

### 9.4. Пилотный пример

Реальный комплект — 7 счетов-проформ и 7 упаковочных листов (14 страниц скана): 40 строк, 129 шт, найденные находки (неверный итог, одинаковое наименование с разными кодами, повторяющийся номер паллеты). Эталон лежит в `docs/golden/UZ95-039-045-2026_expected.json`, подробное описание предметной области — в `docs/invoice-to-excel-spec.md`. Исходный PDF в репозитории не хранится (документ заказчика): передаётся отдельно, контрольная сумма SHA-256 `51b4f8775a22fcd2b35543a9808c51d3c20a698f21ae6cca29a7c3f4d9dedec6`. Использовать как один из тестов, но не как единственную область применения.

## Приложение B. Пример профиля (формат иллюстративный)

```yaml
profile: proforma_invoice
languages: [ru, es]
numbers: {decimal: ",", thousands: " ", currency_position: any}
tables:
  - name: lines
    columns:
      - {name: pallet,     type: integer}
      - {name: article,    type: id}
      - {name: qty,        type: integer}
      - {name: name_ru,    type: text}
      - {name: hs_code,    type: id, pattern: '^\d{10}$'}
      - {name: unit_price, type: money}
      - {name: value,      type: money}
    rules:
      - {id: R1, expr: "qty * unit_price == value", tolerance: 0.005}
      - {id: R2, expr: "sum(value) == totals.total", tolerance: 0.005, on_fail: finding}
pair_with:
  profile: packing_list
  match: by_row_order          # не по названию колонки (раздел 8, п. 12)
  rules:
    - {id: P1, expr: "invoice.article == packing.article"}
    - {id: P2, expr: "invoice.qty == packing.qty"}
```
